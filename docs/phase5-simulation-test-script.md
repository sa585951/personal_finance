# Phase 5 Simulation Test Script

此文件用來模擬一趟接近真實出國情境的完整測試。目標是驗證目前 MVP 的資料流、畫面操作、分帳邏輯、幣別換算、帳戶扣款、月報顯示與 AI 快速輸入是否一致。

此文件分成兩部分：

- 現階段可測：目前 Web / PWA MVP 已實作或可用 dev bypass 測試的流程。
- 第一版多人可測：邀請連結、接受邀請、重新加入、owner/editor/viewer 權限與共享交易查詢。

## 多使用者帳本可見性

目前資料結構與 API 已具備多人帳本第一版：

- `trips.owner_user_id` 代表旅行帳本建立者。
- `trip_members.user_id` 若綁定某個真實使用者，且 `status = active`，該使用者可看到這個旅行帳本。
- `trip_members.user_id = null` 代表目前的外部旅伴，只能用來分帳，不代表該旅伴已經能登入並看到帳本。
- `trip_invites` 代表 owner 建立的邀請連結，token 只存 hash，原始 token 只在建立時回傳。

目前已完成：

- owner 建立/關閉邀請連結。
- 受邀使用者接受邀請後加入帳本。
- 曾退出的使用者可用有效邀請重新加入。
- active member 上限先固定為 15 人。
- owner / editor / viewer 權限控制。
- 已加入帳本的使用者可看到共享旅行交易。
- 個人帳戶資訊仍隔離，不顯示其他使用者的帳戶名稱或餘額。

目前仍暫緩：owner 手動新增的外部旅伴與真實登入使用者自動合併。第一版接受邀請會建立或重新啟用該登入使用者自己的 member，避免因同名造成誤合併。

## 現階段可測流程

### 1. 啟動環境

1. 啟動 PostgreSQL。
2. 啟動後端。
3. 啟動前端。
4. 開啟首頁。

預期結果：

- 首頁可載入。
- 導航可切換。
- dev bypass 下不需要正式登入。

### 2. 帳戶建立與餘額

操作：

1. 到帳戶頁新增「台幣銀行」。
2. 新增「台幣現金」。
3. 新增「日幣現金」。
4. 新增「信用卡」，設定為不追蹤餘額。
5. 測試台幣帳戶互轉。

預期結果：

- 追蹤餘額的帳戶會顯示餘額。
- 不追蹤餘額的帳戶不應強迫輸入或更新餘額。
- 轉帳後來源帳戶扣款，目標帳戶增加。
- 不同幣別轉帳時，換算結果符合 `target_per_source_rate = target_amount / source_amount`。

### 3. 日常收支

操作：

1. 新增收入：薪資 68000 TWD，帳戶選「台幣銀行」。
2. 新增支出：午餐 150 TWD，帳戶選「台幣現金」。
3. 新增支出：訂閱費 390 TWD，帳戶選「信用卡」。
4. 測試切換收入 / 支出。
5. 測試刪除日常交易。

預期結果：

- 收入與支出分類清楚分開。
- 台幣現金餘額應扣除午餐。
- 信用卡若不追蹤餘額，不應出現餘額扣款問題。
- 日常收支頁不顯示旅行交易。
- 首頁近期紀錄會顯示日常交易。

### 4. AI 快速輸入

操作：

1. 在收支頁輸入「早餐麥當勞 150 元，用現金」。
2. 套用解析結果並建立交易。
3. 輸入一筆解析成功但不建立交易的文字。
4. 輸入一筆解析失敗的文字。
5. 展開 AI 解析紀錄面板。

預期結果：

- 可解析出金額、類型、類別或帳戶提示。
- 建立交易後 parse event 狀態變成 `confirmed`。
- 解析成功但未建立交易，狀態顯示為未採用。
- 解析失敗時不應建立交易。

### 5. 建立旅行帳本

操作：

1. 建立「日本關西測試」，預設 JPY，計入日常統計。
2. 建立「韓國週末測試」，預設 KRW，旅行獨立統計。
3. 測試旅行帳本列表切換。
4. 測試封存與解除封存。
5. 測試軟刪除與還原。
6. 測試永久刪除。

預期結果：

- 旅行帳本可建立成功。
- 封存後可在封存區看到。
- 解除封存後回到一般列表。
- 軟刪除後可在刪除暫存區看到。
- 還原後回到一般列表。
- 永久刪除後不可再還原。

### 6. 旅伴管理

操作：

1. 在日本帳本新增 Amy、Ben、Cara。
2. 嘗試刪除未參與任何分帳的 Cara。
3. 建立一筆包含 Amy 的分帳後，再嘗試刪除 Amy。
4. 嘗試刪除 owner。

預期結果：

- 未被交易或分帳引用的外部旅伴可刪除。
- 已被交易或分帳引用的旅伴不可刪除。
- owner 不可刪除。

### 7. 旅行支出：自己付款

操作：

1. 在日本帳本新增支出：拉麵 1200 JPY。
2. 付款人選「我」。
3. 帳戶選「日幣現金」。
4. 匯率使用提示值或手動輸入 0.22。
5. 分帳方式先用均分：我、Amy、Ben。

預期結果：

- 交易明細顯示 1200 JPY。
- 台幣估算約為 264 TWD。
- 日幣現金餘額扣 1200 JPY。
- 我的旅行成本只算自己的分攤額，不是整筆 1200 JPY。
- 建議結算可看出 Amy / Ben 應付給我。

### 8. 旅行支出：他人付款

操作：

1. 新增支出：計程車 3000 JPY。
2. 付款人選 Amy。
3. 不選自己的扣款帳戶。
4. 分帳成我、Amy、Ben 均分。

預期結果：

- 不應扣我的任何帳戶餘額。
- 我的旅行成本增加自己的分攤額。
- 建議結算應顯示我可能要付給 Amy。

### 9. 旅行支出：自訂分攤

操作：

1. 新增支出：燒肉 10000 JPY。
2. 付款人選我。
3. 自訂分攤：
   - 我 4000 JPY
   - Amy 3000 JPY
   - Ben 3000 JPY
4. 再新增一筆除不盡支出：便利商店 1000 JPY，三人均分。

預期結果：

- 自訂分攤總額必須等於交易金額。
- 除不盡時，餘數歸付款人。
- 分帳摘要可清楚看出誰應付誰。
- 建議結算以箭頭方式呈現，例如 `Amy -> 我 JPY 3000`。

### 10. 旅行支出計入日常統計

操作：

1. 在日本帳本新增支出。
2. 到首頁查看月報。
3. 到收支頁查看日常收支。
4. 在韓國帳本新增支出。
5. 再回首頁查看月報。

預期結果：

- 日本帳本因計入日常統計，首頁月報與近期紀錄應看得到相關支出。
- 收支頁維持日常收支，不顯示旅行交易。
- 韓國帳本未計入日常統計，首頁月報與近期紀錄不應計入其旅行支出。
- 預算頁不應被旅行支出吃掉。

### 11. 結算與收尾檢查

操作：

1. 查看建議結算。
2. 複製結算文字。
3. 新增一筆付款確認。
4. 檢查建議結算是否減少。
5. 撤銷付款確認。
6. 嘗試編輯已結算相關交易。

預期結果：

- 結算建議清楚顯示誰付誰。
- 複製內容可貼到通訊軟體。
- 付款確認後，待結算金額下降。
- 撤銷後，待結算金額回復。
- 編輯已結算相關交易時應出現提醒。
- 收尾檢查區塊顏色與狀態應容易判讀。

### 12. 匯出與核對

操作：

1. 匯出旅行核對資料。
2. 檢查 CSV 或複製文字內容。

預期結果：

- 現階段至少應能產生可複製內容。
- 若未來改成直接下載 CSV，需再測：
  - 檔案名稱。
  - 欄位順序。
  - 金額格式。
  - 幣別與匯率。
  - 分帳與結算紀錄。

## 邊界狀況清單

### 金額與匯率

- 金額為 0：應阻擋。
- 金額為負數：應阻擋。
- 匯率為 0：應阻擋或提示。
- 匯率為空：若幣別與基準幣不同，應提示使用者。
- JPY / TWD 顯示 0 位小數。
- USD / EUR 顯示 2 位小數。
- `1 original_currency = exchange_rate base_currency` 顯示方向不可反。

### 帳戶扣款

- 自己付款且選自己帳戶：應扣款。
- 他人付款：不應扣自己的帳戶。
- 不追蹤餘額帳戶：不應造成餘額異常。
- 交易刪除或還原後，帳戶餘額是否正確回復需特別驗證。

### 分帳

- 分攤人不可為空。
- 分攤總額不可超過交易金額。
- 自訂分攤總額不可小於交易金額。
- 旅伴已被分帳引用後不可刪除。
- 付款人應可不在分攤名單中，但 MVP 建議優先避免這種情境。

### 旅行帳本

- 結束日期不可早於開始日期。
- 封存帳本不應出現在一般 active list。
- 軟刪除帳本不應出現在一般 list。
- 刪除暫存區可還原或永久刪除。
- 被永久刪除後不應再顯示。

### 首頁與月報

- 日常支出一定進月報。
- 計入日常統計的旅行支出進首頁月報與首頁近期紀錄。
- 旅行獨立統計的旅行支出只在旅行帳本查看。
- 預算維持日常預算，不吃旅行預算。

### AI 解析

- 解析成功但未採用：應顯示未採用。
- 解析成功並建立交易：應顯示已採用。
- 解析失敗：應顯示失敗。
- 解析結果套用後，使用者仍應可手動修正。

## 多人邀請測試腳本

此段可用自動化測試驗證核心資料流；正式登入與部署環境的端到端驗證仍需在後續實際部署後補測。

### 預期資料

| 代號 | 狀態 | 預期 |
|---|---|---|
| Owner | 已登入 | 建立旅行帳本並產生邀請連結 |
| Amy | 未加入 | 打開邀請連結後登入並加入 |
| Ben | 已加入 | 可看到帳本，但權限受 role 限制 |
| Cara | 被移除 | 不可再看到帳本 |

### 預期流程

1. Owner 建立旅行帳本。
2. Owner 新增外部旅伴 Amy。
3. Owner 產生邀請連結。
4. Amy 開啟邀請連結並登入。
5. 系統為 Amy 建立或重新啟用自己的 `trip_members`。
6. Amy 進入旅行列表，可看到該帳本。
7. Amy 若是 editor，可新增支出。
8. Amy 若是 viewer，只能查看，不可新增或修改。
9. Owner 移除 Amy 後，Amy 不可再看到帳本。

### 本地 dev bypass 手動測試流程

在本地前後端都開啟 dev bypass 時，可用前端右上角的測試使用者切換器模擬多人：

1. 一般視窗選擇 `Dev User`。
2. `Dev User` 建立旅行帳本，進入旅伴頁建立邀請連結。
3. 開無痕視窗，右上角切換為 `Amy`。
4. `Amy` 打開邀請連結並加入帳本。
5. `Dev User` 將 `Amy` 設為 `editor`，確認 Amy 看得到「記支出」tab 並可新增自己的旅行支出。
6. `Dev User` 將 `Amy` 改為 `viewer`，確認 Amy 重新整理後只剩檢視型 tab，且不能再編輯或刪除自己過去建立的交易。
7. 切換為 `Ben` 或 `Cara`，確認與該使用者無關的待結算建議不顯示「已付款」按鈕。
8. 確認只有 `Dev User` owner 可以看到旅行管理中的封存、刪除與復原操作。

### 已新增的自動化測試

- owner 可建立 invite。
- 同一趟旅行同時間只允許一組 active invite。
- 同一使用者重複接受邀請會回傳已加入，不建立 duplicate member。
- 使用者退出後可透過有效 invite 重新加入。
- active member 達 15 人上限後不可再加入。
- invite 關閉後不可再使用。
- 被邀請者接受後，`trip_members.user_id` 正確建立或重新啟用。
- active member 可 list / get trip。
- removed member 不可 list / get trip。
- viewer 不可新增、修改、刪除。
- viewer 前端不顯示新增支出入口。
- editor 可新增交易，但只能修改/刪除自己建立的交易。
- editor 被降為 viewer 後，不可再修改/刪除自己過去建立的交易。
- owner 可修改/刪除其他成員建立的旅行交易。
- 只有 owner 或付款方本人可確認建議結算。
- 只有 owner 或結算記錄者可撤銷已確認結算。
- 共享交易可見，但帳戶資訊不洩漏給非帳戶擁有者。

### 已新增的 MVP 自動化測試

`tests/test_phase5_mvp_simulation.py` 目前已覆蓋：

- 10 人旅行帳本建立。
- 外部旅伴新增與未使用旅伴刪除。
- 自己付款時連動自己的帳戶餘額。
- 他人付款時不連動自己的帳戶餘額。
- 平均分攤與除不盡餘數歸付款人。
- 自訂分攤合計必須等於交易金額。
- JPY 不允許小數。
- 匯率與金額必須大於 0。
- 已被付款、分攤或結算引用的旅伴不可刪除。
- 日常交易與旅行交易分流。
- 計入日常統計的旅行支出會進首頁月報，旅行獨立統計的旅行支出不會進首頁月報。
- 結算確認與交易刪除後帳戶餘額回補。

## 判定標準

Phase 5 可視為通過的最低標準：

- 日常收支、帳戶、預算、旅行帳本、分帳、結算的主要流程都可順利完成。
- 首頁月報與旅行支出是否併入的邏輯不會讓使用者困惑。
- 自己付款與他人付款時，帳戶扣款行為正確。
- 分帳結果能回答「我這趟實際花多少」與「誰該給誰多少」。
- AI 快速輸入至少能處理常見日常收支，不破壞手動輸入流程。

若上述流程通過，才建議進入下一階段：多人邀請、正式登入、部署前驗證與商品化 UI 收斂。
